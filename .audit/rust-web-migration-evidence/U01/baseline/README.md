## Safety and fixture boundary

The isolated worktree was at the requested source SHA. The separate `/workspace/hrflow-pwa` checkout was not accessed. The source `.firebaserc` and `src/lib/firebase.js` defaults point to Firebase project `attendance-108ba`; this environment was not demonstrably non-production, so no account was used and no Firebase project was contacted. `firebase.json` has no emulator configuration, and no local Firebase emulator was running. Existing React tests are logic tests, not a signed-in UI fixture harness. The Dioxus attendance prototype has its own synthetic data but is not the React app's role/module fixture, so it was not used as React evidence.

For a safe build, the published source was archived to a temporary directory outside the worktree. All six `VITE_FIREBASE_*` build-time values were overridden with inert dummy values; the resulting `dist` was checked and did not contain the source-default project identifier. The preview bound only to `127.0.0.1`. Chromium used a fresh temporary profile, DNS rules allowing only loopback, and a CDP request interceptor that blocked every non-loopback request. The only external request observed was to `fonts.googleapis.com`; it was blocked. No Firebase request, sign-in, form submission, business mutation, real employee data, or payroll data was used. The blocked font means the screenshots use the browser's fallback font, not the remote Inter font.

The fixture for every captured screen was therefore **a fresh, signed-out, empty browser state**. The email/employee-ID and password fields were not filled; the password dots visible in the screenshots are the field's placeholder. Only the email/employee-ID input was clicked to measure focus response. The protected `/` route was also opened once and redirected to `/login`.
