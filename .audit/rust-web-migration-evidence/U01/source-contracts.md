# U01 Source-Contract Inventory

> **Scope.** This is a **source-contract inventory only** for the 16 mapped product areas, based on the supplied structured findings and migration plan/map. It does not inspect business data or live Firebase; it makes no deployed Firebase-rule claims; it is not a complete Unit 1 signoff. It does not assert a role-surface matrix, read/write freeze, screenshots, or performance baseline. Client display/navigation behavior is kept distinct from authorization and deployed behavior. The inspected baseline was `c191ae98a8789e1b5cb93edcd904182ceb8f36e2`; unrelated worktree changes were not modified (docs/RUST_WEB_MIGRATION_PLAN.md:L30-L32; docs/RUST_MODULE_MIGRATION_MAP.md:L72-L72).

## 1. App shell, sign-in, organization context, navigation and client runtime

- `BrowserRouter` exposes public `/login`, protected `/`, `/mobile`, compatibility redirects for `/tasks` and `/tasks/checklist`, and a wildcard redirect; `ProtectedRoute` waits for auth, redirects signed-out users to `/login`, and sends authenticated mobile/small-screen users to `/mobile` with replacement navigation (src/App.jsx:L43-L78,L80-L120).
- `AuthProvider` listens to Firebase `onAuthStateChanged`, resolves `users/{uid}`, restores a minimal user when that document is absent, sets signed-out state to null, and tears down the listener; organization selection prioritizes `targetOrgId`, `currentOrgId`, the first membership, then legacy `orgId`, reads `organisations/{orgId}`, resolves membership role, loads `organisations/{orgId}/roles`, and merge-syncs divergent org fields (src/contexts/AuthContext.jsx:L25-L62,L76-L119,L126-L179).
- Auth uses browser-local persistence; Firestore uses automatic long-poll detection and IndexedDB persistence with warnings for multiple tabs/unimplemented browsers (src/lib/firebase.js:L1-L36). Client permissions are derived from role/module flags: admin receives all actions, employee receives view/export defaults plus restricted Vehicle create, and unknown non-admin roles fall back to defaults; `usePermission` returns false without a user. These are UI checks, not authorization (src/contexts/AuthContext.jsx:L63-L108; src/hooks/usePermission.js:L4-L31).
- Desktop navigation registers the mapped modules and filters non-admin tabs by action flags; home and portal remain visible. Desktop URL state normalizes task/advance subviews and blocks navigation away from unsaved attendance/advance changes. Mobile uses an in-memory tab registry, category filtering, and an admin/non-admin Vehicles split (src/pages/Dashboard.jsx:L225-L256,L300-L350,L354-L402; src/components/MobileDashboard.jsx:L245-L266,L367-L434,L750-L787).
- Organization create/join writes organization and user membership fields with separate `setDoc` operations, not a transaction/batch (src/contexts/AuthContext.jsx:L335-L416). Organization switching clears selected browser storage/IndexedDB/service workers on a best-effort basis; this does not prove Firebase persistence was fully cleared (src/components/ui/OrganizationSwitcher.jsx:L65-L132).
- Production PWA registration uses `virtual:pwa-register` with immediate update and visibility refresh; VitePWA generates the manifest, injects `sw-push.js`, cleans caches, and permits 10 MB cached files. Firebase Hosting and Vercel each provide separate rewrite/cache source configurations (src/main.jsx:L12-L40; vite.config.js:L20-L42; firebase.json:L9-L30; vercel.json:L1-L17). Push/task notifications depend on browser Notification and service-worker APIs (src/hooks/useTaskNotifications.js:L1-L10,L47-L80; src/lib/pushNotifications.js:L97-L124).
