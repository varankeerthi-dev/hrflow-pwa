# HRFlow native design system

## Direction

The Android surface is **warm, confident, approachable, high-contrast, and mobile-first** while retaining the clear information hierarchy and privacy-first restraint required by HR workflows. The visual mood is loosely informed by the quick scanability, color confidence, rounded touch surfaces, and decisive actions common to Indian food-ordering apps such as Zomato. This is mood reference only: HRFlow does not use Zomato's logo, product branding, icons, illustrations, or distinctive screen layouts.

Use a restrained coral accent, soft warm-white canvas, clean white content surfaces, expressive chips, and generous rounded cards. **Do not add a vertical left-edge stripe or colored metric-card bars.** Let labels, hierarchy, selected chips, and clear primary actions carry emphasis; statuses must never rely on color alone. Keep content density readable on a phone and preserve HRFlow's real role, privacy, and access boundaries.

## Color tokens

| Token role | Native value | Usage |
| --- | --- | --- |
| Brand coral / primary | `#C2413A` | Primary action, selected navigation, focus and key emphasis; 5.1:1 contrast with white. |
| Brand coral dark | `#A43732` | Pressed emphasis and text on a pale coral surface; 6.6:1 with white. |
| Brand coral tint | `#FFEFEB` | Selected chips and soft information surfaces. |
| Warm canvas | `#FFF9F5` | Light app background and the outer preview canvas. |
| Warm surface | `#FFFFFF` | Cards, app bar, forms, dialogs, and readable content surfaces. |
| Warm 100 / 200 | `#FFF2EB` / `#F0DED5` | Soft card/chip fills, separators, and borders. |
| Warm text 500 / 700 / 800 / 900 | `#826E66` / `#59443D` / `#362821` / `#211814` | Secondary text through primary headings; retain contrast on warm surfaces. |
| Success / warning / danger | `#087F5B` / `#9A5B08` / `#B42318` | Status accents only, always paired with explicit text or icon semantics. |

The dark color scheme is defined for future explicit opt-in; the current root continues to select the light scheme and does not silently track system dark mode.

## Type, shape, and touch

Inter is the UI family for headings, body text, labels, and controls. The official Inter variable font is bundled at `app/src/main/res/font/inter_variable.ttf`, referenced from Compose typography, and rendered into the static previews; the SIL Open Font License is included as `app/src/main/res/raw/inter_ofl.txt`. Source: [rsms/inter](https://github.com/rsms/inter). No font is downloaded at runtime. Use the font's weight axis rather than introducing a second display family; keep headings expressive through size and weight, not decorative type.

`HrFlowSpacing` uses a 4 dp baseline (4, 8, 12, 16, 24, 32, 48 dp). Compose shapes use 6/10/14/20/28 dp radii, with restrained 2/4/12 dp card/raised/overlay elevation. Prefer at least 48 dp interactive targets, readable supporting text, and layouts that adapt to Android font scaling and narrow widths; Android accessibility takes precedence over pixel parity with the raster preview.

## Components and content rules

- Use Material 3 controls colored by `HrFlowTheme`; make primary actions clear and touch-friendly without adding actions whose workflow or role is not approved.
- Use warm surfaces and borders to separate groups. Do not use a colored vertical rail/stripe as a card decoration.
- Keep loading, error, and empty states distinct and accessible. A failed or unauthorized query must not be represented as an empty list.
- Treat account role fields as display hints only. They do not provide security authorization.
- Keep employee and organization information blank or omitted from static concepts. Never imply that placeholder metrics or controls are live.
- Do not broaden sign-in, profile access, role resolution, organization switching, Firebase reads/writes, or sharing behavior as a visual-design side effect.

The active tokens live in `app/src/main/java/com/example/hrflow/ui/theme/HrFlowTheme.kt`; `FeedbackStates.kt` contains shared loading, error, and empty-state patterns. Preview artwork is generated by `design-preview/render_ui_preview.py`; verify actual density, Inter weight rendering, large text, and TalkBack on an Android device before implementation sign-off.
